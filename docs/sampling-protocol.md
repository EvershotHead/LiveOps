## 3. 视频采样协议

五类配额（每游戏 40-60 个视频）：

| 类别 | 目标数量 | 检索词策略 | 采样理由记录 |
|---|---|---|---|
| 官方物料 | 6-14 | 官方号（原神/鸣潮官方）版本 PV、前瞻、角色演示 | 官方节奏基准 |
| 攻略解析 | 6-14 | "版本号+攻略/深渊/阵容/测评" | 高信息密度玩家 |
| 体验评价 | 6-14 | "版本号+体验/评价/一个月后" | 观点表达密集 |
| 二创内容 | 6-14 | "版本号/新角色名+二创/MMD/手书/MV" | UGC 情绪与扩散 |
| 争议讨论 | 6-14 | "版本号+节奏/争议/退坑/对比" | 负向与冲突信号 |

- 每个入选视频记录：`search_term_used / search_rank / sampling_reason / sampled_at / stats_snapshot`。
- 检索时间与结果排名快照存入 `data/raw/<study>/search_journal.jsonl`。
- 任何单一视频评论数 ≤ 该游戏样本 10%（配额校验器强制）。

## 4. 评论采样协议

- 覆盖三种模式：热门评论（按点赞）、时间序列（按页序）、楼中楼（parent 关系保留）。
- 每视频采样上限 = min(400, 配额计算值)，避免头部视频垄断。
- 限制单作者（anon_user_id 去重后采样上限 10 条）、复制文本（规范化阶段模糊去重）。
- 抽奖/广告/刷屏/重复/疑似无关单独打 flags，不静默删除（审计可见）。

## 5. 采集合规护栏（代码强制）

1. 仅访问公开页面与公开 JSON 接口；不登录采集登录后专属内容，不绕过验证码/风控。
2. 令牌桶限速：评论接口 ≥ 2.5s/请求，元数据 ≥ 1.5s/请求，单会话 ≤ 2,000 请求。
3. 响应码 -412/-352、验证码跳转 → **hard_stop**：停止采集、写日志、状态 `collection_blocked`，不重试不换 UA。
4. 断点续采：journal JSONL 每 50 条 fsync；重启从上次位置继续，不重复。
5. 原始 uid 不落盘：采集时立即 HMAC-SHA256（study 盐）匿名化。
6. 采集不可行 → 切换「视频 URL 清单 + 文件导入」模式（正式能力，非降级补丁）。

## 6. 导入模式（正式路径）

- 支持 CSV / XLSX / JSON / JSONL；最少字段 `text / published_at / source_url`。
- 字段映射：系统推荐（别名匹配，确定性）→ 用户确认 → Pydantic 校验 → 行号级错误报告。
- URL 清单模板见附录 A。

## 附录 A：视频 URL 清单模板

```json
[
  {
    "video_id": "BV1xx411c7mD",
    "url": "https://www.bilibili.com/video/BV1xx411c7mD",
    "title": "（可选）标题",
    "category": "official | guide | review | fanwork | controversy",
    "sampling_reason": "为什么选这个视频",
    "search_term_used": "检索词或'人工推荐'",
    "search_rank": 0
  }
]
```

评论数据文件字段建议：`text, published_at, source_url, likes, reply_count, rpid, bvid, parent_id, user_key`（user_key 将被匿名化）。
