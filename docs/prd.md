# PRD：LiveOps Community Intelligence v1

## 1. 一句话定位

面向游戏版本运营的、**固定可复现可审计**的 B 站社区评论分析流水线与运营复盘工作台：数据导入/合规采集 → Canonical Schema → 相关性过滤 → 主题/立场/情绪/反讽/诉求标注（模型+人工两层）→ Python 量化聚合 → 原文证据回溯 → 版本复盘报告。

**不是**：通用情感分析工具、LLM 评论总结套壳、实时舆情监控系统。

## 2. 目标用户与场景

| 用户 | 场景 |
|---|---|
| 游戏运营/社区运营 | 版本上线后复盘：哪些议题升温、哪里失血、玩家在要什么 |
| 用户研究/策划 | 从"所采样的 B 站讨论"回到代表性原文，验证二手结论 |
| 求职者（本作品） | 展示游戏理解 + 社区运营思维 + 数据工程 + LLM Agent 工程的完整闭环 |

## 3. 核心用户故事

1. 作为运营，我导入一份评论导出文件（CSV/XLSX/JSON/JSONL），确认字段映射，选择版本窗口，一键创建分析任务，看到成本预估。
2. 作为运营，我在总览页看到主题分布、正负信号、风险与机会列表，每个数字都能点开看统计口径和代表性原文。
3. 作为运营，我在双游戏对照页看到相同相对时间窗口、归一化口径下的讨论结构差异，页面明确提示"不输出胜负结论"。
4. 作为标注员，我在标注工作台用键盘流标注/复核种子标注，所有修改留痕（字段级 diff + 原因）。
5. 作为面试官，我打开公开演示站（无密钥），看到两个真实版本案例的完整分析、证据、评测和方法说明。

## 4. 版本范围（MVP）

- 双游戏：《原神》6.8、《鸣潮》3.5（版本锁定证据见 sampling-protocol.md）。
- 平台：仅 B 站；文本+元数据，不分析视频画面/语音。
- 每游戏 4,000-5,000 条有效评论、40-60 视频、单视频 ≤10%、五类视频覆盖。
- 时间窗 T-7 ~ T+28（预热/上线/发酵三段）。

## 5. 功能需求（按页面）

| 页面 | 核心功能 | 验收要点 |
|---|---|---|
| 数据与任务 | 导入向导（文件→映射预览→版本配置→运行）、进度、断点续跑、成本预估 | 缺最少字段报行号错误；损坏文件友好提示 |
| 总览 | 数据覆盖、主题分布、正负信号、风险/机会 | 每结论挂口径+证据 |
| 版本时间线 | 以 T0 为中心的主题/情绪/争议变化 | 三段窗口清晰 |
| 主题洞察 | 主题×立场×情绪×时间×视频类型筛选 | 筛选联动 |
| 社区争议 | 冲突话题、观点矩阵、回复链、代表性证据 | 楼中楼对立可见 |
| 双游戏对照 | 归一化指标对比 + 样本差异提示 | 无胜负表述 |
| 证据与审核 | 原文、来源、模型标签、置信度、人工修正、导出 | 全部证据链接可点 |
| 模型评测 | Macro-F1/混淆矩阵/弃权率/ECE/成本/吞吐 | 真实数字，未测显示"未测量" |
| 运营报告 | 六段式复盘 + 打印 PDF | 验证节点通过才可导出 |

## 6. 非功能需求

- 单机单任务（文件锁）；阶段级断点续跑；无 Redis/Celery/多租户。
- 所有运行记录数据集哈希、模型、提示词版本、代码版本、成本、耗时、错误。
- 公开演示无密钥只读；公开数据匿名化不可逆。
- 测试：Pytest（后端 132+ 用例）、Vitest、Playwright（桌面+移动）。

## 8. 明确不做

实时全网监控、绕过平台风控、用户画像、舆情操纵预测、视频画面分析、无监督微调、通用 Agent 评测平台、"代表所有玩家"的表述。
